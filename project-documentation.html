1. ภาพรวมโครงงาน (Project Overview)

ชื่อโครงงาน

Community Stray Pet Watch — แพลตฟอร์มแจ้งจุดสัตว์จรจัดป่วย/ดุร้าย และหาบ้านเพื่อชุมชน

วัตถุประสงค์

  1. ให้ประชาชนสามารถ แจ้งเหตุฉุกเฉิน เกี่ยวกับสัตว์จรจัดที่บาดเจ็บ ป่วย หรือดุร้าย ผ่านแผนที่แบบ Real-time
  2. ให้ประชาชนสามารถ ประกาศหาบ้าน ให้สัตว์จรจัดที่ต้องการการดูแล
  3. ให้ เจ้าหน้าที่ สามารถรับเรื่องและติดตามสถานะการช่วยเหลือได้อย่างเป็นระบบ
  4. ให้ ผู้ดูแลระบบ (Admin) สามารถบริหารจัดการผู้ใช้งานและโพสต์ต่าง ๆ ได้
  5. แจ้งเตือนอัตโนมัติเมื่อมีเหตุเกิดใกล้บ้านผู้ใช้

กลุ่มเป้าหมาย

  • ประชาชนทั่วไปที่ต้องการรายงานสัตว์จรจัดหรืออยากรับเลี้ยง
  • เจ้าหน้าที่หน่วยงานท้องถิ่น, อาสาสมัคร, มูลนิธิช่วยเหลือสัตว์
  • ผู้ดูแลระบบ (Admin) สำหรับบริหารจัดการ

5. ระบบ Authentication & User Roles

5.1 การเข้าสู่ระบบ (Authentication)

ระบบใช้ Firebase Authentication ผ่าน Google Sign-In (OAuth 2.0) เพียงวิธีเดียว เมื่อผู้ใช้ล็อกอินครั้งแรก ระบบจะสร้าง Document ใน users Collection โดยอัตโนมัติ กำหนด Role เริ่มต้นเป็น "user"

5.2 บทบาทผู้ใช้งาน (User Roles)

บทบาทไอคอนคำอธิบาย
user 👤 ผู้ใช้งานทั่วไป — สามารถดูแผนที่, ดูฟีด, แจ้งเหตุ, แก้ไข/ลบโพสต์ของตัวเอง, ตั้งค่าการแจ้งเตือน
official 🛡️ เจ้าหน้าที่ — ทำทุกอย่างเหมือน user + กด "รับเรื่อง" เคสที่แจ้งเข้ามา + เปลี่ยนสถานะเคส + เข้าถึงหน้า Official Dashboard + แก้ไขโพสต์ได้ทุกโพสต์
admin 🔴 ผู้ดูแลระบบ — ทำทุกอย่างเหมือน official + เข้าหน้า Admin Dashboard จัดการ Role ผู้ใช้ + ลบโพสต์ของผู้ใช้คนอื่น

5.3 การป้องกันหน้าเว็บ (Route Guards)

Guard Componentหน้าที่ป้องกันRole ที่อนุญาต
AdminGuard/adminadmin เท่านั้น
StaffGuard/officialadmin + official

หากผู้ใช้ที่ไม่มีสิทธิ์พยายามเข้าหน้าเหล่านี้ ระบบจะ Redirect กลับไปหน้าแรก / โดยอัตโนมัติ

7. รายละเอียดแต่ละหน้าของเว็บไซต์

7.1 หน้าแรก — /

ส่วนคำอธิบาย
Hero Bannerแบนเนอร์ขนาดใหญ่ แสดงชื่อเว็บ จุดเด่น ปุ่ม CTA "แจ้งเหตุฉุกเฉิน" และ "ประกาศหาบ้าน"

แผนที่ Longdo Mapแผนที่ Interactive ขนาดใหญ่แสดง Marker สัตว์จรจัดทุกตัว, วงกลมรัศมีค้นหา, Popup รายละเอียด, ค้นหาสถานที่, GPS
ค้นหาตามรัศมีSidebar: ปรับรัศมี (1-50 กม.), ค้นหาสถานที่, ดึง GPS, แสดงรายการใกล้เคียง
ฟีดรายการแสดงรายการทั้งหมดพร้อม Filter (ประเภท, สถานะ, สัตว์) + Search + Sort + Toggle Grid/List

7.2 หน้าฟีดรายการ — /feed

ส่วนคำอธิบาย
Report Listแสดงรายงานทั้งหมด พร้อมระบบกรอง (Filter) ตามประเภท, สถานะ, ชนิดสัตว์ และค้นหาด้วยข้อความ
Sort Optionsเรียงตาม: ล่าสุด, ใกล้สุด, ด่วนที่สุด
View Toggleสลับมุมมองระหว่าง Grid (การ์ด) และ List (รายการ)

7.3 หน้าแจ้งเหตุ — /report

ส่วนคำอธิบาย
ฟอร์มแจ้งเหตุฟอร์ม Multi-step สำหรับกรอกข้อมูล: เลือกประเภท (ฉุกเฉิน/หาบ้าน), ชนิดสัตว์, หมวดหมู่, ความรุนแรง, อัพโหลดรูป, ปักหมุดแผนที่, กรอกรายละเอียด
Location Pickerแผนที่ Longdo Map ให้ปักหมุดจุดเกิดเหตุ พร้อมช่องค้นหาสถานที่ และ GPS
Image Uploadอัพโหลดรูปภาพ แปลงเป็น Base64 แบบ Compress ก่อนบันทึก

7.4 หน้ารายละเอียดโพสต์ — /report/[id]

ส่วนคำอธิบาย
Full Report Viewแสดงรายละเอียดทั้งหมดแบบเต็มหน้า: รูปภาพ, หัวข้อ, คำอธิบาย, ที่อยู่, ระดับความรุนแรง, สถานะ, ข้อมูลผู้แจ้ง, แผนที่
ปุ่มจัดการปุ่ม: แก้ไข (เจ้าของ/admin/official), ลบ (เจ้าของ/admin), รับเรื่อง (official/admin), เปลี่ยนสถานะ (official/admin)
ข้อมูลเจ้าหน้าที่ผู้รับเรื่องแสดงรูปโปรไฟล์, ชื่อ, และเวลาที่เจ้าหน้าที่กดรับเรื่อง
Real-time Updateข้อมูลอัพเดทแบบ Real-time ผ่าน Firestore onSnapshot

ส่วนคำอธิบาย
Edit Formใช้ ReportForm ตัวเดียวกับหน้าแจ้งเหตุ แต่โหลดข้อมูลเดิมมาเติมในฟอร์มอัตโนมัติ สามารถแก้ไขทุกฟิลด์ได้

7.6 หน้าโปรไฟล์ — /profile

ส่วนคำอธิบาย
ข้อมูลส่วนตัวแสดงรูปโปรไฟล์, ชื่อ, อีเมล จาก Google Account

7.7 หน้าพื้นที่เจ้าหน้าที่ — /official

ส่วนคำอธิบาย
Tab: รอรับเรื่องแสดงเคสทั้งหมดที่สถานะ active (ยังไม่มีใครกดรับเรื่อง) พร้อมตัวเลขจำนวน
Tab: งานของฉันแสดงเคสที่สถานะ in_progress เฉพาะที่เจ้าหน้าที่คนนี้เป็นคนกดรับเรื่อง
Tab: ประวัติแสดงเคสที่ resolved เฉพาะที่เจ้าหน้าที่คนนี้ดูแล
Report Detail Popupคลิกการ์ดเพื่อเปิดรายละเอียด กดรับเรื่องหรือปิดเคสได้จากหน้านี้

8. ระบบ Components หลัก

8.1 MapComponent (Longdo Map)

  • แสดงแผนที่ Longdo Map ของประเทศไทย
  • แสดง Marker สำหรับสัตว์จรจัดแต่ละตัว ด้วยไอคอนที่แตกต่างตามประเภท
  • แสดง Popup HTML (ชื่อ, รูป, สถานะ, ปุ่ม "ดูรายละเอียด" / "แก้ไข") เมื่อคลิก Marker
  • แสดงวงกลมรัศมีค้นหา (Radius Circle)
  • รองรับการค้นหาสถานที่ผ่าน Longdo Map Search API
  • รองรับการคลิกแผนที่เพื่อเปลี่ยนจุดศูนย์กลางค้นหา

8.2 ReportForm (ฟอร์มแจ้งเหตุ)

  • รองรับ 2 โหมด: สร้างใหม่ (Create) และ แก้ไข (Edit)
  • ฟอร์มแบบ Multi-step: เลือกประเภท → กรอกรายละเอียด → ปักหมุด → อัพโหลดรูป → ส่ง
  • รองรับ Image compression ก่อนอัพโหลด
  • ดึงชื่อและรูปโปรไฟล์ผู้ใช้มาแนบอัตโนมัติ

8.3 ReportDetail (Popup รายละเอียด)

  • แสดงผลเป็น Dialog (Modal) ที่เด้งขึ้นมาเมื่อคลิกการ์ด
  • แสดงทุกข้อมูลของรายงาน: รูป, ชื่อ, คำอธิบาย, สถานะ, ความรุนแรง, ที่อยู่, ผู้แจ้ง, ข้อมูลติดต่อ
  • ปุ่ม "รับเรื่อง" สำหรับ Official/Admin (เปลี่ยน status active → in_progress)
  • ปุ่ม "เปลี่ยนสถานะ" (Resolved / Adopted)
  • ปุ่ม "แก้ไข" / "ลบ" (ตามสิทธิ์)

8.4 ReportList (รายการ + Filter)

  • แสดงรายการทั้งหมดแบบ Responsive (Grid / List view)
  • รองรับการกรอง: ประเภท, หมวดหมู่, สถานะ, ชนิดสัตว์, คำค้นหา, ระยะทางสูงสุด
  • รองรับการเรียงลำดับ: ล่าสุด, ใกล้สุด, ด่วนที่สุด

8.5 LocationNotifier (ระบบแจ้งเตือน)

  • ทำงานเบื้องหลัง (Background) ตรวจสอบรายงานใหม่ที่เข้ามา
  • เปรียบเทียบพิกัดบ้านผู้ใช้กับพิกัดรายงานใหม่
  • แสดง Toast แจ้งเตือนหากอยู่ภายในรัศมีที่ตั้งค่าไว้
  • ไม่แจ้งเตือนโพสต์ของตัวเอง / โพสต์เก่าที่โหลดครั้งแรก

10. ระบบการแจ้งเตือน (Notification System)

ระบบแจ้งเตือนทำงานผ่าน LocationNotifier Component ที่ทำงานเบื้องหลังในทุกหน้า:

  1. ผู้ใช้ตั้งค่า "บ้านของฉัน" ด้วยการปักหมุดบนแผนที่ในหน้า Profile
  2. ผู้ใช้ตั้ง รัศมีการแจ้งเตือน (1-20 กม.) ผ่าน Slider
  3. เมื่อมีรายงานใหม่เข้ามา ระบบจะ คำนวณระยะทาง ระหว่างพิกัดบ้านกับพิกัดรายงานใหม่โดยใช้สูตร Haversine Formula
  4. หากอยู่ภายในรัศมี → แสดง Toast Notification แจ้งชื่อเหตุการณ์และระยะทาง
⚠️ ระบบแจ้งเตือนทำงานเฉพาะเมื่อผู้ใช้ เปิดเว็บไซต์อยู่ เท่านั้น (ไม่ใช่ Push Notification จากเซิร์ฟเวอร์) ระบบใช้ Firestore onSnapshot สำหรับ Real-time listening

11. Firestore Security Rules

ระบบใช้ Firestore Security Rules เพื่อป้องกันการเข้าถึงฐานข้อมูลที่ไม่ได้รับอนุญาตทั้งฝั่ง Client และ API:

Collection: reports

สิทธิ์เงื่อนไข
Readอนุญาตทุกคน (Public feed/map)
Createต้องล็อกอิน + ต้องตั้ง reporterId เป็น UID ของตัวเอง
Updateเจ้าของโพสต์ หรือ Admin หรือ Official
Deleteเจ้าของโพสต์ หรือ Admin เท่านั้น

Collection: users

สิทธิ์เงื่อนไข
Readตัวเอง หรือ Admin
CreateAdmin สร้างได้ทุกคน / ผู้ใช้สร้างโปรไฟล์ตัวเองได้ (role ต้องเป็น "user")
UpdateAdmin แก้ไขได้ทุกคน / ผู้ใช้แก้ไขตัวเองได้ แต่ ห้ามเปลี่ยน Role ตัวเอง
🔒 ป้องกัน Privilege Escalation: ผู้ใช้ไม่สามารถเปลี่ยน Role ตัวเองเป็น admin หรือ official ผ่าน API ได้ มีเพียง Admin เท่านั้นที่ทำได้ผ่านหน้า Admin Dashboard

12. ฟีเจอร์เด่นของระบบ

#ฟีเจอร์รายละเอียด
1Real-time Dataข้อมูลทุกอย่างอัพเดทแบบ Real-time ผ่าน Firestore onSnapshot ไม่ต้องรีเฟรชหน้า
2Longdo Map Integrationแผนที่ไทยแบบ Interactive ค้นหาสถานที่, ปักหมุด, แสดง Marker, วงกลมรัศมี, Popup รายละเอียด
3Proximity-based Notificationแจ้งเตือนอัตโนมัติเมื่อมีเหตุเกิดใกล้บ้าน ตามรัศมีที่ตั้งค่าไว้
4Role-based Access Controlแบ่งสิทธิ์ 3 ระดับ (user, official, admin) ป้องกันทั้ง Frontend และ Database rules
5Case Tracking Systemระบบติดตามเคส 4 สถานะ พร้อมบันทึกเจ้าหน้าที่ผู้รับเรื่อง
6PWA Supportติดตั้งเป็นแอปบนมือถือได้ผ่าน Service Worker + Web App Manifest
7Responsive Designรองรับทุกขนาดหน้าจอ (มือถือ, แท็บเล็ต, คอมพิวเตอร์) ด้วย Mobile-first approach
8Google Authenticationล็อกอินด้วย Google Account ปลอดภัย สะดวก ไม่ต้องจำรหัสผ่าน
9Image Compressionรูปภาพถูก Compress ก่อนบันทึก ลดขนาดข้อมูล
10Serverless Architectureไม่ต้องดูแล Backend Server — ลดค่าใช้จ่ายและความซับซ้อน
11Thai Language UIอินเทอร์เฟซภาษาไทยทั้งหมด รองรับฟอนต์ Prompt
12Official Dashboardพื้นที่ทำงานเฉพาะเจ้าหน้าที่ แบ่ง Tab (รอรับ / งานฉัน / ประวัติ)
